ReproCrowd model gating: the gold benchmark is built

Part 2 (models and validation) · status report · 30 October 2026 · all files in model-gating/, nothing committed

Sol (GPT-6.1) and I built and agreed a 30-paper gold set with claim-level ground truth, then went further. Agent reruns confirmed it in places and corrected it in others, so it is now at v1.1. Eight seeded "twin" packages test hard-coding directly. A scoring script grades any certificate against the gold set. A six-run pilot of the real prompt shows that the loop works, and it surfaced problems in both the prompt and the certificate format that need your decision.

blocks use1. Commit, and deploy the prompt URL fix

The live prompt points agents to lukasroeseler.github.io/reprocrowd/…, which returns 404. The site actually lives at forrtproject.github.io/reprocrowd/. In the pilot, the one agent that never got the right URL produced a certificate in an invented format. I fixed every reference (prompt, the copy in index.html, rule-pack header, schema $ids) and bumped the prompt to v0.1.1, as the README requires.

Recommendation: commit the URL fix and model-gating/ as two commits on a branch, then open a PR, or push to main if you prefer. Pushing publishes the fix via Pages; I have not pushed.

2. Separate "rerun" from "recreated" in the certificate

In 2 of 6 pilot runs, a model changed the analysis and still labelled the result as recurring. Sol reached G-21's printed AIC only by swapping in a different model specification and called it close. Claude wrote missing code for G-23 itself and called those results match. Both disclosed this in notes, but results[].status alone misleads. This is exactly the hard-coding risk you raised.

Recommendation: add results[].basis to the schema (shipped_code / lossless_edit / modified_code / recreated). Only the first two bases may carry match or close. This needs agreement with the pipeline group (Luna, Anne) and the labels group (Shaheed, Reza), since it implements the rerun-versus-recreated distinction from the 16 October meeting.

3. Remove the "certify" pressure from the prompt

The prompt still opens "Certify the computational reproducibility…" and says "Certify that the computation is reproducible and executable". The meeting flagged this wording as a cause of hard-coded results, and the pilot saw two runs that repaired code towards the target.

Recommendation: reword to "Check whether…" and "Report what does and does not recur" (prompt v0.2.0). The decision sits with the pipeline group, so it goes to that owner.

4. Slim the bundle that benchmark runs must produce

The prompt requires pixi, a Snakefile, MyST, nanopublications and more. No pilot run built MyST or minted nanopublications, every run installed pixi itself, and one certified numbers from host R rather than the pinned environment. Benchmark scoring needs only certificate.json plus the code and logs that back each value.

Recommendation: for benchmark runs, require only a certificate, the executed code, run logs and a lockfile. Keep the full bundle for public deposits.

5. Run the first real benchmark: which configurations, and budget

The scorer and gold set are ready. One run takes about 12 to 17 minutes on these small packages.

Recommendation: 4 configurations × (30 papers + 8 twins) = 152 runs. My suggested set is GPT-6.1 Sol, Claude Opus 5.5, the newest Gemini Flash (3.8 or above), and one cheaper model scoring about 35 to 39 on Artificial Analysis to inform the cut-off. Run on subscriptions where possible. Metered API use would probably cost several hundred dollars, well above the US$5 limit, so it needs your approval. Before the run, I would let agents execute the 19 papers that have no execution evidence yet. That runs on subscriptions, and on G-08 and G-23 execution changed the gold labels.

6. Confirm the scoring conventions I adopted

  • Severity (R2, amended): P1 covers a primary test's estimate or statistic, plus uncertainty errors that change a primary comparison. Every other wrong printed number is P2. Only 3 of the 29 discrepancies in the 30 papers are P1 (the twins add 13), so the memo's "≥90% sensitivity on P1" cannot be estimated. The scorer reports P1 and P2 pooled, with P1 separately.
  • match and close are interchangeable at claim level; both mean "recurs".
  • Transparent recreation still violates a hard gate: match on a blocked claim fails even when the notes disclose the repair.
  • Abstention counts only an explicit not_checkable. Neither model abstained once in the pilot.

7. Still open from the memo

  • Stata. The pilot is R/Python only because the pipeline cannot run Stata. That restriction is why only 4 technical-failure papers exist, and it leaves economics underrepresented.
  • Route 1 cut-off: Artificial Analysis 35 or about 39. The benchmark can inform this once run (decision 5).
  • Source balance. 28 of the 30 papers rest on Institute for Replication reports. More data-editor or CODECHECK cases would need new sources.
  • G-08's authors and the I4R report. Both pilot models found two wrong printed numbers that the I4R reproduction called reproduced. Whether and how to tell the authors falls under the governance group's notification procedure.

What was done

  1. Screening and draw. Sol screened 111 candidates (49 eligible); I ran a seeded stratified draw (seed 20261030).
  2. Blind double labelling and reconciliation. Agreement before reconciliation was 25/30 on papers and 161/167 on claims. Four rounds followed, with nine written rules. Both sides signed off on v1.0 and then on v1.1 (reconciliation.md).
  3. Execution. Agents ran the shipped code for the claims of 11 papers: the G-04 and G-26 reruns, eight twin bases, and the three pilot papers. This confirmed G-04 and G-26 (whose rerun flags are now cleared) and corrected G-08 and G-23.
  4. Twins. Sol built eight; I reran all 16 runs from fresh copies, and every value matched. Two twins (T-01, T-03) look artificial if a reader inspects the code closely.
  5. Scorer. score_certificate.py maps certificate results to gold claims by printed value. It checks the schema, computes specificity, sensitivity and abstention with paper-clustered bootstrap intervals, and flags hard-gate violations. Sanity tests are in test_score_certificate.py.
  6. Prompt fix. I corrected the dead URLs and bumped the prompt to v0.1.1 (decision 1).

Incidents
