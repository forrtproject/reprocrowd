**What “eligible” means here.** A public human report was read, an original package or an openly downloadable mirror was located, its file inventory was inspected, and the reported computational outcome appears mappable to numerical claims. Runtime is a screening estimate unless the CSV explicitly attributes a timing to the source. I did not execute complete statistical workflows. Eligibility therefore remains provisional: confirm a pinned package, 5–8 suitable claims and the laptop runtime before a candidate enters the random draw. The report excerpts and named tables suggest a mapping within an hour; I have not timed that mapping. Broad paper-level successes do not certify every figure or every supplementary analysis.

All eligible records are R/Python-compatible at the scoped analysis stage. R scripts printed in a supplied PDF or HTML were accepted provisionally; this needs review below. A mixed package requiring SPSS, Stata, MATLAB, JASP or other unverified software was excluded rather than silently treating an R component as the whole workflow. A reproducer's use of Stata does not by itself make the *original* R package a Stata package. `language_ok=false` also covers absent or unknown executable code. No restricted-data, registration or data-use-agreement exception was made.

`package_size_mb` uses decimal MB and totals the deposited files inspected through repository metadata, including public child components and linked GitHub trees where found. It is not necessarily the expanded size of every compressed archive or the minimal run subset. Some projects include ancillary materials. Small code/data files and selected small archives were downloaded to check the inventories; large HF LFS packages were not downloaded. `data_open=true` records observed public analysis inputs, not a claim that every raw acquisition file or every auxiliary dataset is available. Failure to reach an endpoint is distinguished from missing data.

**The source labels were not imported as ReproCrowd verdicts.** I used the original-code computational reproduction sections, excluding altered models, corrected scientific coding, alternative estimators and robustness exercises. For candidate issues, `discrepant` and severity P1/P2 still require independent adjudication at a numerical claim. P3 display differences alone do not establish this stratum. P0 requires an identified execution blocker, not an HTTP error during screening, a “not reproduced” score, or an unsuccessful robustness exercise. Ambiguous candidates concern specific numerical claims whose reference output depends on an unstated choice; `not_checkable` is the proposed claim status. “Ambiguous” is a sampling stratum, not a new value in the paper-level certificate enum. Some ambiguities may become `close` once an appropriate stochastic tolerance is justified.

**I4R: what is public.** The [reports catalogue](https://www.i4replication.org/reports) contained 416 records across 17 journals when read, rather than the older memo's approximate 411. The separate [papers catalogue](https://www.i4replication.org/papers) also supplies older discussion-paper links. An OSF project's empty root storage is not proof of absent materials: child components, registrations and the GitHub provider can contain them. I followed these where available. Bulk API inspection triggered HTTP 429 and some transient 403/502/timeouts; I slowed requests and retried selected failures. Incomplete inventories were excluded rather than relabelled P0. Public original packages were distinguished from a reproducer's newly written analysis. Primary-article transparency statements helped locate a few original packages when report links alone were incomplete.

I4R is useful for numerical comparison tables but frequently combines computational reproduction, corrected analyses and robustness. Authors' responses sometimes change the correct interpretation of a report. The most consequential exclusions and retained edge cases are listed below. There is no claim here that I4R's scientific criticism is wrong; it is simply outside this benchmark unless unchanged shipped code fails to recover the printed number.

**SCORE: claim data are public, individual materials vary.** I opened the [Nature article](https://www.nature.com/articles/s41586-026-10203-5), [living OSF repository](https://osf.io/ed8pj/) (DOI 10.17605/osf.io/ed8pj), and its [18 March 2026 analyst archive](https://osf.io/download/cs8up/), an 8,713,973-byte ZIP. The archive contains `analyst data.RData`, analysis/helper R scripts, dictionaries and a readme. I read the RData and exported the tables locally; the CSV evidence URLs for these rows point to that actual archive. Per-project transparency trails and public original materials were then inspected for the selected papers.

The raw `repro_outcomes` table has 651 rows. Keeping `repro_version_of_record=TRUE` gives 586; excluding COVID rows leaves 555; removing four outcome `none` rows yields **551 claims across 143 papers**. The resulting outcomes are 253 push-button, 91 precise, 102 approximate, 100 not reproduced and five not attemptable. Thus 344 claims are push-button/precise and 446 are reproduced if approximate is included. These are claim counts, not independent papers, and they should not be inflated by counting superseded attempts.

SCORE distinguishes Push Button, Extended Push Button, Author Data and Source Data reproduction. Repairs and independent recreation cannot automatically demonstrate a defect in shipped original code. Its approximate-effect tolerance of 15% and p-value tolerance of .05 are also much looser than a rounding-based ReproCrowd comparison; “approximate” is not an automatic P1/P2 label, and “precise” does not settle every rounding tolerance. “Not attemptable” alone does not identify a P0 cause. The original materials range from public complete packages to data only, code supplied on request and stale project links. I did not treat data-availability fields as proof that executable original code is public.

Ten SCORE papers remain in the 90-row audit, of which only SC-8R9d is provisionally eligible, as ambiguous. Their DOI/title pairs were checked against Crossref. Examples excluded: SC-AvOr and SC-E4Am have original code supplied on request; SC-J0Yv and SC-0qar use new author-data reconstruction without original shipped analysis code; SC-rjb has only three assessed claims and no established 5–8-claim mapping; SC-LbEB's four joined claims lack original numeric reference fields; SC-GJe4 says “not attemptable” without a verified precise fatal cause. SCORE's discrepancy for SC-zK2 is an Author Data reproduction in a non-pilot workflow, not a demonstrated unchanged-R-code failure.
