What is ReproCrowd?

Many researchers already attempt to reproduce the results of papers in their field, but in an unsystematic way. We provide a standardized prompt, a way for you to sign and submit results, and the means to disseminate your reports in a human- and machine-friendly way.

    Share & compare

    The report lands in FLoRA with an AI tag, and anyone can re-run your reprocheck or comment. Reports are comparable because the engine and model are recorded.

Prompt

Tell your coding agent (Claude, Codex, DeepSeek, …) to certify the computational reproducibility of a paper. The agent needs nothing else. The rule pack is referenced by the prompt and pinned in the report.

ReproCrowd certification prompt 
ReproCrowd certification.
Prompt version: 0.1.0.

Certify the computational reproducibility of this paper: run its shipped code and data as a
Reproduction Study (same methodology, same tools) and record faithfully what reproduces and
what does not. Do NOT upload the original data or code; the licence may not permit it. Link to
them instead.

Work in a new directory `-certification` and produce the whole reproducible bundle, so the
folder can be re-run from scratch. It must contain ALL of these files:
- myst.yml (the reproducible-report config)
- pixi.toml and pixi.lock (the pinned environment, every dependency versioned)
- Snakefile (the end-to-end workflow; `snakemake --cores 1` re-runs it)
- notebooks/01_data_download.py, 02_data_clean.py, 03_analysis.py, 04_figures.py
- environment.json (the full program inventory: host OS, interpreter versions, package versions, lockfile)
- nanopubs/PUBLISHED.md (the FORRT nanopublication chain URIs)
- CITATION.cff (the citation metadata)
- certificate.json, certificate.md, SIGN-OFF.md, flora-entry.json (the report and sign-off)

Certify that the computation is reproducible and executable. Do NOT rule on whether the
scientific conclusion is correct. Use the FORRT nanopublication chain vocabulary. Report the
engine, model + provider, rules version, and environment you used.

Follow the ReproCrowd rule pack (https://forrtproject.github.io/reprocrowd/crowd-repro/RULEPACK-v1.1.0.md).
If that URL is unreachable, treat the artefact list above as the requirement and do not skip
any of the files.

How to use it

  1. Copy the prompt. Add the paper's article link or DOI and the code & data link at the bottom.
  2. Feed it to your LLM. Paste it into the coding agent you already use, in a fresh directory.
  3. Run it. The agent reads the rule pack, builds the reproducible pipeline, and certifies the computation.
  4. Submit. The agent writes certificate.json, certificate.md, SIGN-OFF.md and flora-entry.json; you save the folder to the repo.
  5. Get signed. A human reviews the single SIGN-OFF.md, verifies the artifacts, and approves it for FLoRA.

Reports are comparable because the rule pack version, engine, model and provider are all recorded in the report. The exact prompt is saved as prompt.txt. See the rule pack v1.1.0.

Submit a reproduction

Upload the <slug>-certification folder your agent produced. We check it contains everything a fully reproducible FORRT reproduction needs, then you sign it off. Contributors can download the bundle and submit it via a GitHub issue, or push it with git.

Warning: this is a proof of concept and has no backend yet, so uploads do not actually go anywhere. The folder is only validated in your browser; nothing is submitted. To publish a real reproduction, use the git or GitHub-issue steps below.

Report checklist

found · required, missing · recommended (full reproducibility, optional)

    Sign off

    The prompter (the person who nominated the paper) reviews and signs the single SIGN-OFF.md. Signing confirms it is a numerical/computational reproduction, not a robustness test, and accepts it into FLoRA with the AI-generated tag.

    A complete, self-reproducible reproduction folder carries the report artefacts (certificate.json, certificate.md, SIGN-OFF.md, flora-entry.json), the pipeline and pinned environment (myst.yml, pixi.toml/pixi.lock, Snakefile, environment.json), and the record (nanopubs/PUBLISHED.md, CITATION.cff), so anyone can re-run the certification, not just read it. The original data and code are never uploaded; only linked, since their licence may not permit redistribution.
